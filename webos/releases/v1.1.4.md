# Plezy webOS 1.1.4

Browsing performance optimisations, in separate commits and priority order:

1. Reuse card bounds within each D-pad decision; skip the candidate scan on the first poster's sidebar exit. Bounds are refreshed for every keypress.
2. Measure only the first grid row and the next row's starting card when calculating alphabet-grid columns and stride, instead of scanning the entire loaded window.
3. Batch artwork geometry reads before assigning image sources, avoiding interleaved layout reads and writes while retaining the two-request limit and fade-in.

4. Replace pending library-entry frame polling with a page-completion focus handoff, fixing a timing-dependent toolbar focus trap caught in CI.

Regression coverage checks focus destinations, geometry-call bounds, alphabet alignment in CSS Grid and Chromium 53's flex fallback, image loading order and concurrency. Playback, ratings and API behaviour are covered by the existing full suite. CI must pass unit tests, browser tests, bundle compatibility and IPK packaging before publication.

Physical LG TV performance and live playback have not been measured. These changes reduce browser work; no frame-rate or wall-clock speedup is claimed.
