# Plezy webOS 1.2.3

- Ensure previously seen library artwork is immediately visible when revisiting the library, including images without a server-provided artwork revision. Keep those images in session memory only, never persistent storage, so freshness across sessions is preserved.
- Check the browser's already-decoded direct-image cache before skipping the 300 ms fade; images genuinely unavailable on the first frame still fade on arrival.
- Render library page cards in one off-DOM fragment so cached posters don't visibly appear eight at a time. Keep viewport-gated image loading and its two-request concurrency limit.
- Raise the recently decoded memory cache from 48 to 128 images without increasing the 12 MiB byte limit, allowing an entire typical previously visited library page to remain ready.
- Explicitly round the cast-page portrait image itself to avoid square corners during Chromium 53's opacity transition.
- Remove the transient Home and navigation-rail "Loading..." labels.
- Add regression tests for first-frame full-library reuse, session-only image memory, rounded cast portrait transitions and Home startup loading.

Physical LG webOS validation remains needed for device-specific browser image and storage behavior.
