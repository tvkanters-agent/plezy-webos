# Plezy webOS 1.15.3

## Restore original one-buffer resume in both playback modes

- Revert the unnecessary second buffer added in 1.15.1 for legacy Plex HLS resumes. The original Plezy webOS player already started native playback at the resume timestamp in a single buffering pass.
- **Enhanced playback Off and On** now both pass the exact resume timestamp to LG's native media pipeline *before* loading or playing the source. No follow-up HTML `currentTime` seek occurs on LG, whether the source is HLS or a supported direct file.
- For compatibility-mode Plex playback, restore the original first-frame startup completion semantics, without the newer decoder-progress heuristics introduced alongside custom playback and subtitles. The strict Enhanced playback feature gate introduced in 1.15.2 remains intact.
- Add unit regressions for the native resume timestamp and lack of a second seek across both modes and both video paths.

The previous black-video report was a regression, not evidence that the LG requires double buffering. Automated tests validate source setup and event sequencing; a physical LG TV is still required to verify native decoding.
