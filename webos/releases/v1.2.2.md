# Plezy webOS 1.2.2

- Remove the seven-day artwork cache expiration. Unchanged, versioned artwork stays cached across app sessions until the existing size/count-based LRU limits require eviction.
- Invalidate cached Plex artwork when the server-provided artwork path timestamp changes, with the owning item's `updatedAt` as a fallback for unversioned direct artwork. Do not misapply an episode's timestamp to inherited show images.
- Use Jellyfin/Emby `ImageTags.Primary` or `SeriesPrimaryImageTag` in artwork URLs and cache identities; changed tags automatically fetch the replacement artwork.
- Artwork without trustworthy version metadata falls back to ordinary loading rather than being cached indefinitely without a way to detect updates.
- Keep cache identity stable across Plezy releases by excluding Plex's `X-Plex-Version` client version from cache keys.
- Preserve bounded disk and memory caching, consistent fades, and graceful fallbacks on webOS 4.x. Tests cover revision changes, app version upgrades, and non-expiring cache behavior.

Artwork freshness is checked when updated metadata is retrieved (e.g. on next library/detail visit or app session); no background polling or repeated image downloads are added.
