# Plezy webOS v1.4.3

- **Larger persistent caches:** 768 MiB artwork and 256 MiB library metadata default disk budgets, scaled down to respect any smaller reported webOS storage quota. No arbitrary limit on the number of images, pages, or titles.
- **First-screen priority:** Keep the top of each library (metadata and artwork) and Home shelf artwork ahead of deep-scroll entries when memory or disk pressure requires eviction.
- **Correct retention:** Frequently revisited library pages update disk recency even on memory hits; library snapshots continue to load before background server refreshes.
- **Practical memory bounds:** Limit catalog metadata to 16 MiB of RAM, compressed images to 24 MiB and decoded images to an estimated 96 MiB. These are separate from persistent storage.
- **Low-overhead cleanup:** Skip full-database eviction scans during normal scrolling. Use webOS-provided quota estimates where available and recover from storage quota errors by pruning lower-priority data before retrying.
- Add regression tests for hundreds of cached library pages and hundreds of images without count-based eviction, and for quota recovery and first-viewport retention.

Existing Home freshness behavior remains unchanged. Tested in CI including browser navigation, Chromium 53 compatibility and IPK packaging; physical-TV performance has not been benchmarked.
